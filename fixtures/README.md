# Fixtures — the generalization

One harness, six domains. Each fixture is a different agent with different durable
artifacts, record formats and crash points, run through the **same** `sweep.py` matrix,
the **same** six verdicts, and the **same** `fixer.py` feedback loop. That is what makes
the method a method rather than one fix.

| fixture | the agent | records extracted from | cache (torn → CORRUPT) | crash@effect (→ DUPLICATE) |
|---|---|---|---|---|
| `refund_bot` (default, at repo root) | refund bot | `ledger.txt` split on `REFUND ` | `cache.json` | torn record, retry appends onto it |
| `file_backup` | backup agent | `manifest.json` JSON array | `cache.json` | entry committed, backup file never landed |
| `scheduler` | job dispatcher | `jobs.txt` lines `id url` | `cache.json` | record written, payload file never landed |
| `indexer` | web crawler | `index.ndjson` lines | `fetch_cache.json` | index line written, progress flag never set |
| `mailer` | email sender | `outbox.csv` rows `id,to,receipt` | `drafts.json` | row written, sent flag never set |
| `order_processor` | order/charging agent | `journal.json` JSON array | `pending.json` | order committed, mark_done never reached |

Every fixture's before-matrix shows the same six verdicts, and the interaction cell
`(crash@effect, bad_url)` is the compound `DUPLICATE+GARBAGE` in all of them. Every
after-matrix is all green.

## Layout

```
fixtures/<name>/
  workflow.py           buggy agent (the thing under test) -- stdlib only
  workflow.fixed.py     rule-fixer template (the floor under GATE 3)
  spec.py               exports FIXTURE: records, validity, crash points, seed assert, fix spec
```

`spec.py` is the only fixture-specific code. It declares:

- `records(fs)` / `record_valid(r)` — how the classifier extracts and judges a unit of work
- `parseable` — the artifact that must stay valid JSON (CORRUPT)
- `crash_points` — label → `CRASH_AT` step number (the two rows beyond `clean`)
- `seed_assert(label, fs)` — proves the seeded dirty state actually took
- `fix_spec` — the prose the LLM fixer is told (generated by `make_fix_spec`)

## Run

```bash
.venv/bin/python localsim.py                       # all fixtures, locally (no sandboxes)
.venv/bin/python sweep.py --fixture file_backup    # one fixture on Daytona
.venv/bin/python fixer.py --fixture indexer        # feedback loop for a fixture
.venv/bin/python fixtures_report.py                # combined matrices -> report_fixtures.html
```

`refund_bot` is the default for every tool, so `python sweep.py` behaves exactly as before.
